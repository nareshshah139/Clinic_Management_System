# VX-03: Nested layouts follow viewport breakpoints, not their own width

## Problem
**Root cause.** Components nested inside fractional page columns pick their column count with *viewport* variants (`md:`, `xl:`). These respond to the window width, not to the width the component actually has.

**Verified on Pharmacy Desk.** `app/dashboard/pharmacy/page.tsx:385` puts `PartnerDailySync` in half of `main` (`xl:grid-cols-2`, about 580px at 1440), and three viewport breakpoints fire at once:

| Rule | Location | Effect at 1440 |
|---|---|---|
| `xl:grid-cols-2` | `pharmacy/page.tsx:385` | `PartnerDailySync` gets about 580px |
| `xl:grid-cols-[minmax(0,1.25fr)_minmax(360px,0.75fr)]` | `components/pharmacy/PartnerDailySync.tsx:370` | Manual Daily Entry gets about 165px |
| `md:grid-cols-4` | `PartnerDailySync.tsx:378` | four inputs in 165px |

The result: labels overprint, and Add Item/Submit stack one letter per line (made worse by VX-01).

**Suspected on Visits.** The medicine table is `min-w-[1080px]` inside its own `overflow-x-auto` (`components/visits/PrescriptionBuilder.tsx:5071-5073`), yet `main` overflows:

| Viewport | `main` scrollWidth vs clientWidth |
|---|---|
| 1440 | 1408 vs 1184 |
| 768 | 1408 vs 512 |
| 375 | 1400 vs 375 |

So some flex or grid ancestor without `min-w-0` is passing the table's min-content width up to `main`.

The system already uses container queries in one place (`components/ui/card.tsx:22`, `@container/card-header`) but not for content. Tailwind 4.1.13 has container variants built in.

**Findings covered:** PH-02, VIS-03, VIS-21, PH-13, PH-24, PH-18, INV-05, P15, D21.

**Evidence:**
- `pages/visits/audit.json → extra.mainHorizontalOverflow` and `extra.footerButtons`: Create Prescription spans x1261–1440 and is clipped.
- PH-13 Counter: +82px at 375.
- INV-05 Stock: 15,092px tall at 375, with sideways scroll.
- P15 (patients table): 1124px in a 1084px container.

**Acceptance criteria:** see `problems.md §VX-03`, criteria 1–5.

## Options considered

**A — Minimal: patch the offending pages.**
- `pharmacy/page.tsx:385` → `2xl:grid-cols-2`.
- `PartnerDailySync.tsx:370` → `2xl:`.
- `PartnerDailySync.tsx:378` → `lg:grid-cols-2 2xl:grid-cols-4`.
- Add `min-w-0` to the visit-form ancestors.
- Fix Counter at 375.

This is quick, but the next component placed in a half column breaks the same way, and the breakpoints remain guesses about what the parent will be.

**B — Restructure: container queries as the design-system rule.**
- `Card` becomes a size container (`@container/card`).
- Component-internal grids use container variants (`@md:`, `@xl:`, `@3xl:`) instead of viewport variants.
- Viewport variants are allowed only in pages and `components/layout/`.
- The `Table` wrapper becomes `@container/table`, and columns can be marked `priority="secondary"` so they hide below a container width.
- Visit-form ancestors get `min-w-0`, so the wide medicine table scrolls only inside its own wrapper.
- A source test enforces the rule.

**C — Convention: stacked list rows for every table on narrow widths.** Shopify Polaris IndexTable renders "condensed" stacked rows on small screens, and Gmail and Linear show list items rather than grids on mobile. Forms use one column until the *container* has room. C is B plus a stacked-row renderer for every data table.

C is the best experience for the long Stock table on a phone. But building and maintaining a second renderer for every table is L effort, and with priority columns plus in-wrapper scroll, B already brings the 375 Stock page under 4,000px.

## Decision
**B. A's concrete page fixes go in as the first commit so the P0s close quickly; C's stacked rows are deferred, to be revisited for inventory Stock only if criterion 4 fails.**

1. **`components/ui/card.tsx:10`:** add `@container/card` to the `Card` base classes. Existing `@container/card-header` usage is unaffected.
2. **Rule** (recorded in the primitive's doc comment and in this decision):
   - Inside `components/**` other than `components/layout/**`, column counts use container variants.
   - Pages (`app/**`) may use viewport variants for page-level columns only.
   - Grid and flex children that hold text or tables get `min-w-0`.
3. **`PartnerDailySync`**
   - Add `@container` to its root.
   - `:370` becomes `grid grid-cols-1 gap-6 @4xl:grid-cols-[minmax(0,1.25fr)_minmax(320px,0.75fr)]`.
   - `:378` becomes `grid gap-4 @lg:grid-cols-2 @3xl:grid-cols-4`.
   - Leave `pharmacy/page.tsx:385` as it is: the child now adapts to its own width.
4. **Visit form**
   - Find the first ancestor of `PrescriptionBuilder.tsx:5072` where `scrollWidth > clientWidth`, and add `min-w-0` (and `max-w-full` on flex children) at each level from there up to `main`.
   - Give the medicine-table wrapper a visible scroll affordance: an edge shadow via `bg-[linear-gradient…]` local background attachment, using the existing `--border` token.
5. **`components/ui/table.tsx`**
   - Add `@container/table` to the wrapper at :11.
   - `TableHead` and `TableCell` accept `priority?: 'primary'|'secondary'`, where `secondary` is `hidden @3xl/table:table-cell`.
   - Mark secondary columns: patients (ABHA, Referral, Consultation), inventory Stock (cost, MRP detail) and pharmacy queue (secondary metadata).
6. **Pharmacy Counter (375) and KPI tiles:** convert the inner fixed grids to container variants, and give tile values `min-w-0 truncate` with `title`.
7. **Guard:** a Jest source scan fails on `\b(sm|md|lg|xl|2xl):grid-cols-` in `components/{pharmacy,inventory,visits,patients}/**`, except for files listed in `frontend/__tests__/ux/viewport-variant-allowlist.json`. The allowlist starts with today's offenders minus the fixed ones and only shrinks.

## Why this is the best
- **Against A:** A fixes today's screenshots and leaves the cause in place. The next component in a half-width column breaks the same way, and the norm violated is L6 ("components reflow at breakpoints") at the *component* level. B makes the component responsible for its own width, which matches how the design system is already built (`CardHeader` uses a container).
- **Against C:** C is the gold standard for long tables on phones, but it doubles the table implementation. Priority columns plus scrolling inside the wrapper meet the measurable criteria at a fraction of the cost. C stays available for Stock if the 4,000px criterion isn't met.
- **Norms satisfied:** L6 (no overflow at any width), L2 (visit footer actions visible), L4 (one grid), D2 (no crushed columns beside dead space), P1 (Polaris and Primer style in-table scroll with a visible affordance).
- **Costs and what it rules out:** developers have to think in container widths, and the source guard and allowlist need upkeep. Viewport-keyed component grids are ruled out.

## Implementation plan
1. A-commit: the PartnerDailySync container fix, the visit-form `min-w-0` chain and the Counter fix (closes the P0s).
2. `card.tsx` and `table.tsx` container support, plus priority columns.
3. Sweep the allowlisted components on pharmacy, inventory, visits and patients.
4. The source guard.
