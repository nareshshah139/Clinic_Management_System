# VX-04: Load and permission failures shown as empty, zero or "operational"

## Problem
**Root cause.** The design system has an `EmptyState` (`components/ui/empty-state.tsx:6`) but no error or permission state, so each screen invents its own failure handling, and most of them substitute a reassuring fallback:
- `app/dashboard/page.tsx:120-128` always appends "System Status · All systems operational" (severity LOW, rendered with a warning icon and badge). Lines 133-145 use the same item as the fallback when alerts fail to load.
- `page.tsx:150-165`: when today's appointments fail to load, the list becomes `[]`, which renders "No appointments scheduled for today" (:407). Lines 169-178 fall back to zero statistics.
- `app/dashboard/pharmacy/page.tsx:131-137`: any error becomes `setDash(null)`, and Desk renders ₹0 / 0 stock as if real (PH-03; the pharmacist's 403 comes from SEC-08).
- Inventory shows the raw permission string (e.g. "This action requires inventory:item:read (Reference: uuid)") with a Retry button that can't fix a 403 (INV-09).
- The package catalogue shows "Retry Loading" when the catalogue is simply empty (PH-19).
- The patients error state replaces the table behind the modal (P09, BRK-47).
- The AI dock says "unavailable" while its composer stays enabled (PH-21).

**Scope boundary.** `docs/ux-paths/defects.md` already owns the functional "why" (MIS-02, MIS-04, BRK-27, BRK-47, SEC-08). This decision owns how a failed, forbidden or empty section looks and what the user can do from it.

**Findings covered:** D01, D04, PH-03, INV-09, P09, PH-19, PH-21.

**Acceptance criteria:** see `problems.md §VX-04`, criteria 1–5.

## Options considered

**A — Minimal: per-page alerts.**
- On each page, add an `error` state and render the existing `Alert` above the affected card.
- Delete the two hard-coded "operational" items.

Each page writes its own copy, there's no forbidden/error/empty distinction, and zero tiles stay unless each page handles them.

**B — Restructure: one `DataState` primitive with typed outcomes.**
- A new design-system component renders exactly one of five outcomes for a section: loading, **error** (network or 5xx: what failed + Retry), **forbidden** (403: which access is missing + who can grant it, no Retry), **empty** (`EmptyState` + next action) and ready.
- The outcome is classified from `ApiError.status` (`lib/api.ts:5-6`): 401 keeps the existing redirect, 403 is forbidden, and 0/408/5xx are errors.
- Metrics whose data is unknown render "—" (with an accessible name of "Not available"), never 0.
- Screens adopt it section by section.

**C — Convention: inline section errors plus a global status indicator.**
- Stripe Dashboard, Linear and GitHub show section-level inline errors with Retry and never show fabricated zeros. Datadog and Grafana show "No data" rather than 0.
- GitHub and Google Workspace show a dedicated "You don't have access" state, with Request access where it is available.
- System health lives in a status indicator or status page (Statuspage pattern), shown only when degraded.

C is B plus a header-level degraded-status indicator backed by a health endpoint, plus migrating these loaders to TanStack Query (`@tanstack/react-query` is already a dependency) so outcomes come from `isError`/`error`.

## Decision
**B, with two grafts from C:** "—" for unknown metrics, and system status shown only when there is a real, degraded health signal (no permanent "operational" line).

1. **New `frontend/src/components/ui/data-state.tsx`**, exporting:
   - `DataState({ status, error, resource, onRetry, empty, children })`, where `status` is `'loading'|'error'|'forbidden'|'empty'|'ready'`. Alternatively pass `error` and let `classifyError(error)` derive the status.
   - `ErrorState({ resource, onRetry })`: `role="alert"`, an `AlertTriangle` icon and the copy "Couldn't load {resource}. Check your connection and retry." with `<Button variant="outline">Retry</Button>`.
   - `ForbiddenState({ resource, permission? })`: `role="status"`, a `Lock` icon and the copy "You don't have access to {resource}. Ask a clinic admin to grant {permission ?? 'access'}." No Retry. The raw permission key appears only inside a `<details>` "Technical details".
   - `MetricValue({ value, format })`: renders `—` with `aria-label="Not available"` when `value` is null or undefined.

   Layout reuses `EmptyState`'s spacing and type, so all three states look like one family (H5). Add a compact variant (`py-4`) for use inside cards on tool surfaces (D2).
2. **`lib/api-state.ts`:** `classifyError(e: ApiError) → 'forbidden'|'error'` (401 continues to redirect via the existing layout handler).
3. **Adopt it on the audited surfaces**
   - `app/dashboard/page.tsx`: keep separate `statsState`, `alertsState` and `appointmentsState`.
     - Delete the "System Status" pushes at :120-128 and :136-145.
     - Delete the zero fallback at :169-178.
     - Wrap the stat cards, the Alerts card and Today's Appointments in `DataState`.
     - The Alerts card shows "No alerts" when it is empty and the request succeeded.
   - `app/dashboard/pharmacy/page.tsx:131-137`: store `dashState`. Desk KPI tiles use `MetricValue`, and 403 renders `ForbiddenState resource="the pharmacy desk"`.
   - Inventory (`components/inventory/InventoryWorkspace.tsx` permission path, INV-09): use `ForbiddenState`, with no Retry for 403.
   - `PharmacyPackageManager` empty catalogue (PH-19): `EmptyState` with "Create package".
   - `PatientsManagement` (P09): the error renders inside the table region and the open dialog keeps its content.
   - `AgenticPharmacyDock` (PH-21): when unavailable, the composer is `disabled` and the reason is shown inline.
4. **Source guard:** the string "All systems operational" may appear only in a module that reads a health endpoint (Jest source scan).

## Why this is the best
- **Against A:** per-page alerts fix today's screens but leave five different failure styles, and nothing stops the next screen from writing `catch { setData([]) }`. A also doesn't separate 403 from 500, and INV-09 shows that this distinction is the difference between a useful message and a dead-end Retry.
- **Against C:** a health endpoint and a data-layer migration are worth doing, but they are backend and architecture work that this P0 doesn't need. The graft keeps C's essential rule: no permanent "operational" line.
- **Norms satisfied:** C3 (status legible, in words), I3 (errors say what happened and what to do), I8 (error and empty states designed), H4 (warning colour only for real warnings, not for "operational"), C1 (no permission keys in the main copy).
- **Costs and what it rules out:** each section owns a status variable. Silent `catch` blocks that set empty data are no longer allowed in these files (worth a lint follow-up). The dashboard loses its always-present alert row, so an empty Alerts card is now honest.

## Test plan
**Unit (RTL):**
- `<DataState status="error" onRetry={fn}>` → `getByRole('alert')` contains the resource name; clicking Retry calls `fn`.
- `status="forbidden"` → no button named Retry; the text includes "don't have access".
- `status="empty"` renders the supplied action.
- `MetricValue value={null}` renders "—" with an accessible name of "Not available".

**Browser** (request interception, as in `scripts/ux/verify-control-freedom.js`):

```js
// criterion 1: dashboard with alerts and appointments failing
intercept('/api/appointments', 500); intercept('/api/admin/alerts', 500);
await page.goto(base + '/dashboard');
await page.waitForSelector('[role=alert]');
const text = await page.evaluate(() => document.body.innerText);
expect(text).not.toMatch(/All systems operational/);
expect(text).not.toMatch(/No appointments scheduled for today/);
// criterion 2: pharmacist 403 on Desk
intercept('/api/pharmacy/dashboard', 403);
await page.goto(base + '/dashboard/pharmacy?section=desk');
expect(await page.evaluate(() => document.body.innerText)).toMatch(/don't have access/);
expect(await page.$$eval('button', bs => bs.some(b => /retry/i.test(b.textContent)))).toBe(false);
expect(await page.evaluate(() => /₹\s?0(\.00)?\b/.test(document.querySelector('main').innerText))).toBe(false);
// criterion 3: 200 with an empty list → EmptyState with an action
```

Exact endpoint paths come from `lib/api.ts` at implementation time.
