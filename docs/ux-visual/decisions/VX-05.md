# VX-05: Day grid silently hides appointments outside working hours

## Problem
**Root cause.** `components/appointments/DoctorDayCalendar.tsx:405-411` clamps every appointment into `[dayStartMin, dayEndMin]` and does `return null` when the clamped span is empty. The same logic is repeated for the second overlay pass near :446-451.

The window is set as follows:
- If the doctor has working hours, it comes from them (`AppointmentsCalendar.tsx:120-131`, via `loadDoctorDay`/`gridHoursFor`).
- Otherwise it falls back to 09:00–18:00 (`DoctorDayCalendar.tsx:67-72`).

The backend accepts bookings outside that window, so they exist but never render, and the user gets no hint. Today, three of Dr Shravya's appointments (18:30–19:45) are invisible in both Calendar and Slots (`pages/appointments/audit.json → extra.scheduleToday`; orchestrator-confirmed).

Related findings in the same view:
- APT-15: no empty-day state.
- APT-17: at 375, labels spill out of the narrow column and the time is clipped.
- APT-18: hour labels are 12px with 2.20:1 contrast.

Functional neighbours that this decision does not handle: BRK-17 (Slots resets the doctor) and MIN-03 (RoomCalendar is hard-coded to 09–18).

**Findings covered:** APT-01, APT-15, APT-17, APT-18.

**Acceptance criteria:** see `problems.md §VX-05`, criteria 1–5.

## Options considered

**A — Minimal: grow the window to fit the bookings.**
- Compute the grid window as the union of working hours and the day's appointment intervals, rounded out to whole hours and clamped to 00–24.
- Nothing is clamped away any more.

**B — Restructure: keep the window and add an "Outside working hours" strip.**
- Keep the working-hours grid.
- Above or below it, add a collapsible strip, "Outside working hours (3)", listing those bookings as compact rows.
- Add a summary in the grid header.

**C — Convention: a full-day scrollable timeline that opens at working hours.** Google Calendar and Outlook show the whole day, scroll to working hours on open, and shade non-working time. Clinic booking tools (for example Cliniko's appointment book) show out-of-hours bookings in a shaded band, not hidden. C means a 24h timeline as an inner scroll container, auto-scrolled to the first appointment or to the start of working hours, with off-hours shaded.

## Decision
**A, with C's off-hours shading and B's count chip grafted on.**

1. **New pure helper `frontend/src/lib/calendar-window.ts`:**
   `computeGridWindow(work: {startHour:number; endHour:number}, slots: string[]) → { startHour, endHour, outsideCount }`
   - `startHour = min(work.startHour, floor(earliestStartMin/60))`
   - `endHour = max(work.endHour, ceil(latestEndMin/60))`
   - Both are clamped to [0, 24].
   - `outsideCount` counts appointments that are not fully inside working hours.
   - Slots without a valid "HH:MM-HH:MM" are ignored, as today.
2. **`DoctorDayCalendar.tsx`**
   - Derive `dayStartMin`/`dayEndMin` (:386-387 and the twin block at :~446) and the hour-row generation from `computeGridWindow(timeSlotConfig, filteredSchedule.map(a => a.slot))`.
   - Drop the clamp-to-null path for out-of-window appointments. Keep the guard for malformed slots.
   - **Off-hours rows** (graft from C): rows outside `[work.startHour, work.endHour)` get a new token class `bg-[var(--calendar-offhours)]`. Define `--calendar-offhours` in `globals.css` as a muted hatch (`repeating-linear-gradient` over `--muted`), so in-hours and off-hours rows differ by pattern as well as colour. The hour label gets the suffix "· outside hours" (screen-reader text plus a visible small caption on the first off-hours row).
   - Booking rules stay unchanged: off-hours rows are bookable exactly when they are bookable today. This is rendering only, not a policy change.
3. **Header count chip** (graft from B): when `outsideCount > 0`, show `<Badge variant="warning">{n} outside working hours</Badge>` next to the doctor/date controls. Clicking it scrolls the first such tile into view.
4. **Empty day** (APT-15): when `filteredSchedule.length === 0` and the grid isn't loading, show an inline note in the grid header: "No appointments on {date}. Select a free slot to book."
5. **Hour labels** (APT-18): change `text-xs text-gray-400`-style labels to `text-muted-foreground` on `bg-background` (≥4.5:1). Keep the size, which follows the type tokens.
6. **375 labels** (APT-17): tile text uses `min-w-0 truncate` with `title` set to the full label, and the time stays first. VX-01 removes the mid-word breaks.
7. **Slots tab:** `AppointmentScheduler` uses the same `computeGridWindow`, so Calendar and Slots agree.

## Why this is the best
- **Against B:** a separate list takes bookings off the time axis, so a receptionist can't see that a 19:15 booking overlaps an extended 18:30 one. It also adds a second visual pattern for the same objects (H5).
- **Against C:** C is the long-term convention, but it needs the grid to become an inner scroll container and to fit in one screen (L1), which is VX-07's page re-composition. A plus shading gives the same never-hidden guarantee now and doesn't block C later: the helper simply returns 0–24.
- **Norms satisfied:** C3 (state legible: "outside hours" in words and pattern, not colour alone), I8 (empty-day state), A1 (label contrast), L6 (no spill at 375), H4 (warning colour only for the off-hours count).
- **Costs and what it rules out:** the grid grows by however many hours the out-of-hours bookings span, up to 24 rows. The grid can no longer be shorter than the day's bookings.
