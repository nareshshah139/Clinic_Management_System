# VX-02: Dialog primitive isn't contained by the viewport

## Problem
**Root cause.** `frontend/src/components/ui/dialog.tsx:63`. `DialogContent` is `fixed top-[50%] left-[50%] grid w-full max-w-[calc(100%-2rem)] … p-6 sm:max-w-lg`. Its problems:
1. **No height limit.** It has no `max-h` and no `overflow`, so tall forms run off both ends of the screen. 25 of 40 call sites add nothing. The 13 that add `max-h-[80–90vh] overflow-y-auto` scroll the header and footer away along with the body.
2. **Widths are lost.** `cn()` is `twMerge` (`lib/utils.ts:5-7`). A consumer's unprefixed `max-w-4xl` replaces the base `max-w-[calc(100%-2rem)]` but **does not** replace `sm:max-w-lg`, so at ≥640px those dialogs are 512px. Twelve call sites are affected (listed in `problems.md §VX-02`), and below 640px they lose the 1rem side margin. `max-w-sm` and `max-w-md` dialogs are *widened* to 512px.
3. **The footer isn't pinned.** `DialogFooter` (`dialog.tsx:93-103`) is ordinary flow content, so the primary action, and the reason it is disabled, can sit below the fold (APT-03, APT-20).
4. **The close target is 16×16** (`dialog.tsx:70-76`).

**Findings covered:** P03, APT-03, APT-04, APT-20, APT-21, VIS-23, PH-09, VIS-07a.

**Evidence:**
- Create Patient: top −42px, height 985px at 1440×900, `overflowY: visible`, `maxHeight: none`; 1301px at 375; Create can't be reached on a phone (`pages/patients/audit.json → notes.dialog-geom-1440`, `reception-375-createReachable: false`).
- Booking dialog: 512px wide at 1440, Confirm below the fold at every viewport (`pages/appointments/audit.json → extra.dialog`).

**Acceptance criteria:** see `problems.md §VX-02`, criteria 1–6.

## Options considered

**A — Minimal.**
- In `DialogContent`, replace `w-full max-w-[calc(100%-2rem)] … sm:max-w-lg` with `w-[calc(100%-2rem)] max-w-lg`, so any consumer `max-w-*` overrides it cleanly.
- Add `max-h-[calc(100dvh-2rem)] overflow-y-auto`.
- Enlarge the close button.

*After:* nothing extends past the viewport and widths are honoured, but the whole dialog scrolls and the footer can still be below the fold inside it (APT-03 stays unfixed).

**B — Restructure into three regions and a bottom sheet.**
- `DialogContent` becomes `flex flex-col max-h-[calc(100dvh-2rem)]` with a fixed header, a new scrolling `DialogBody`, and a fixed footer with `border-t`.
- A `size` prop replaces ad-hoc width classes.
- Below 640px every dialog becomes a bottom sheet (`max-sm:` anchored to the bottom, `rounded-t-lg`, `max-h-[92dvh]`).
- All 40 call sites migrate.

**C — Convention.** This follows Material 3 (fixed title and actions, scrolling content; *full-screen dialogs on compact widths for complex forms*), Shopify Polaris Modal (`size` small/large/fullScreen, scrolling body, fixed footer), Atlassian Modal Dialog (width presets, scrolling body) and GitHub Primer Dialog (width presets, fixed footer). Specifically:
- Three regions as in B, plus a `size` prop with tokens.
- Below 640px, `lg`-and-up dialogs go **full screen** and `sm`/`md` confirm dialogs stay as centred cards.
- A backward-compatibility rule: until a call site adopts `DialogBody`, the whole content scrolls.

## Scores
Max 60. Compressed run: one agent scored from each lens; no external judges.

| Option | Usability | Visual craft | Engineering |
|---|---|---|---|
| A Minimal | 42 (**fails criterion 2**: footer can be below the fold) | 42 | 44 |
| B Restructure (bottom sheet) | 47 | 49 | 44 |
| **C Convention (full-screen on compact)** | **54** | **52** | **52** |

A is disqualified because B and C both meet criterion 2.

On phones, B's bottom sheet works well for short pickers but badly for 14-field forms like Create Patient: the on-screen keyboard and the sheet's top edge compete for the same space, and a sheet invites swipe-to-dismiss that loses input.

C's backward-compatible overflow lets the 40 call sites migrate gradually without any of them regressing in the meantime, which is why its engineering score is higher.

## Decision
**C**, with A's "unmigrated dialogs still scroll" rule as the backward-compatibility layer.

1. **`dialog.tsx` → `DialogContent`**
   - Add the prop `size?: 'sm'|'md'|'lg'|'xl'|'2xl'|'3xl'|'4xl'|'6xl'|'full'` (default `'lg'`), mapped to `max-w-sm … max-w-6xl`. `full` maps to `w-screen max-w-none h-dvh max-h-dvh rounded-none`.
   - Base classes: `fixed left-1/2 top-1/2 z-50 flex w-[calc(100%-2rem)] -translate-x-1/2 -translate-y-1/2 flex-col gap-4 max-h-[calc(100dvh-2rem)] overflow-y-auto has-[>[data-slot=dialog-body]]:overflow-hidden rounded-lg border bg-background p-6 shadow-md`. Remove `grid`, `w-full`, `max-w-[calc(100%-2rem)]` and `sm:max-w-lg`.
   - Compact rule, for sizes `lg` and above only: `max-sm:left-0 max-sm:top-0 max-sm:h-dvh max-sm:max-h-dvh max-sm:w-full max-sm:max-w-none max-sm:translate-x-0 max-sm:translate-y-0 max-sm:rounded-none`.
2. **New `DialogBody`** (exported): `data-slot="dialog-body"`, `-mx-6 min-h-0 flex-1 overflow-y-auto px-6`.
3. **`DialogHeader`:** add `shrink-0` and right padding so the title never runs under the close button.
4. **`DialogFooter`:** add `shrink-0`. When it follows a body, add `[[data-slot=dialog-body]~&]:border-t [[data-slot=dialog-body]~&]:pt-4`.
5. **Close button:** `absolute top-3 right-3 inline-flex size-9 items-center justify-center rounded-md opacity-70 hover:bg-accent hover:opacity-100 focus-visible:ring-[3px] focus-visible:ring-ring/50 pointer-coarse:size-11`. Tailwind 4.1.13 is installed, so `pointer-coarse:` and `has-[]` are available.
6. **Call-site migration**
   - Replace every consumer `max-w-*`/`sm:max-w-*` and `max-h-*`/`overflow-*` on `DialogContent` with `size`.
   - Width mapping:

     | Current class | `size` |
     |---|---|
     | `sm:max-w-[480–600px]` | `xl` |
     | `sm:max-w-[900px]` | `4xl` |
     | `sm:max-w-5xl xl:max-w-6xl` | `6xl` |
     | `max-w-[100vw] … h-[100vh]` | `full` |

   - Wrap the field area in `DialogBody` first on the form dialogs: `PatientsManagement.tsx:751` (Create/Edit Patient), `AppointmentBookingDialog.tsx:253`, `PharmacyPackageManager.tsx:566,871`, `AddInventoryItemDialog.tsx:182`, `BillingManagement.tsx:842,1409`, `UsersManagement.tsx:534`, `PackageBrowser.tsx:267`.
   - The mobile nav sheet (`dashboard-layout.tsx:145-147`) moves to a `Sheet` primitive under VX-06.
7. **Booking dialog:** put the disabled-Confirm reason (APT-20) in the footer next to the button, so it can't scroll out of view.
8. **Guard:** a Jest source test fails if any `<DialogContent className=…>` contains `max-w-` or `max-h-`.

## Why this is the best
- **Against A:** A stops dialogs running off the screen, but the primary action still scrolls away. This was APT-03's complaint at every viewport. Pinned actions are the norm (L2), and A doesn't deliver them.
- **Against B:** a bottom sheet on a phone suits short, dismissible choices. For a 14-field registration form, a full-screen dialog gives the whole height to fields and keeps the action bar pinned. That is the Material 3 rule for complex forms. B also migrates every call site at once with no fallback, which is riskier.
- **Norms satisfied:** L1/L2 (fits, primary action always visible), L6 (reflow on compact), H5 (one dialog look via size tokens), I4 (36/44px close target), D3 (sizes from tokens, not arbitrary pixels).
- **Costs and what it rules out:** ad-hoc dialog widths are no longer possible, because size is a token. Each call site needs one edit, and form dialogs need a `DialogBody` wrapper. Focus return after close is *not* fixed here, because it depends on focusable openers (VX-10).

## Implementation plan
1. Change the `dialog.tsx` primitive and add `DialogBody`. Update the `ui-primitives` tests.
2. Migrate the form dialogs listed above, then the rest. Remove per-call-site `max-h`/`overflow`.
3. Add the source-scan guard.
4. Re-run the dialog states captured in Phase 2 (patients `dialog-new`/`validation`, appointments `dialog-open`/`dialog-procedure-noroom`, pharmacy `create-package`, inventory `edit-price`/`add-batch`/`manual-request`).

## Test plan
**Unit (RTL):**
- `<DialogContent size="4xl">` has `max-w-4xl` and not `sm:max-w-lg`.
- With a `DialogBody` child, the content has the `has-[…]:overflow-hidden` behaviour, the body scrolls, and the footer is a sibling after the body.
- The close button has `size-9`.

**Browser** (puppeteer-core synthetic fixtures, or Playwright):

```js
for (const vp of [[1440,900],[768,1024],[375,812]]) {
  await page.setViewport({ width: vp[0], height: vp[1] });
  await openCreatePatient();                         // click "New Patient"
  const box = await page.$eval('[data-slot=dialog-content]', e => e.getBoundingClientRect().toJSON());
  expect(box.top).toBeGreaterThanOrEqual(0);
  expect(box.bottom).toBeLessThanOrEqual(vp[1]);     // criterion 1
  const btn = await page.$eval('[data-slot=dialog-footer] button[type=submit]', e => e.getBoundingClientRect().toJSON());
  expect(btn.bottom).toBeLessThanOrEqual(vp[1]);     // criterion 2, without scrolling
  if (vp[0] === 375) expect(box.width).toBe(375);    // criterion 4 (lg → full screen)
}
// criterion 3
await openBookingDialog();
expect(await page.$eval('[data-slot=dialog-content]', e => Math.round(e.getBoundingClientRect().width))).toBe(896);
// criterion 5
const close = await page.$eval('[data-slot=dialog-close]', e => e.getBoundingClientRect().toJSON());
expect(close.width).toBeGreaterThanOrEqual(36); expect(close.height).toBeGreaterThanOrEqual(36);
```

Also check that Escape still closes each dialog and that Tab cycles inside it (a regression guard; Radix behaviour must not change).
