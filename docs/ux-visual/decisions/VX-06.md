# VX-06: App shell — document scroll leak and tablet breakpoint

## Problem
**Root cause 1: the scroll leak.**
- The shell root is `h-screen flex` with no overflow clipping (`components/layout/dashboard-layout.tsx:116`).
- `main` is `min-w-0 flex-1 overflow-auto` but is not positioned (`:159`).
- So any absolutely positioned descendant without a positioned ancestor takes the initial containing block. It sits at its static position far below the fold, and the document grows to contain it. Because its containing block is outside `main`, main's scroller neither clips it nor scrolls it.
- Two cases were found: the `.sr-only` live region in `TabsFontSizeControls` (`components/ui/tabs.tsx:179`, on Pharmacy Billing) and `caption.sr-only` (`components/inventory/WorkflowDocumentEditor.tsx:1084`, on Inventory Reorder).
- The document then scrolls **in addition to** `main`: 476px on Billing at 1440, 642 at 768 and 864 at 375; 1380 on Reorder at 375 (`pages/pharmacy|inventory/audit.json → layout.viewport.pageScrollY`; `_meta.note` says this should be 0). The shell slides away into a white void.
- Suspected same cause: D13, where opening notifications shifts the page up by 9px.

**Root cause 2: the breakpoints.**
- The sidebar is persistent from `md` (768px) at a fixed `w-64` (`dashboard-layout.tsx:118`, `sidebar.tsx:220`), so `main` gets 504px on a portrait tablet.
- The header is one rigid row (`header.tsx:493`). The search is `flex-1 max-w-md` (:496) and shrinks to 56px. The right cluster never collapses: Receptionist "Start Tour", the "Branded" label and switch, bell and settings (`header.tsx:597-620`). Together with VX-01, "Start Tour" wraps to 3–4 lines and overflows the 64px bar.
- Below 768 a separate mobile bar (`dashboard-layout.tsx:134-156`) drops search, bell and settings. The functional side of that is BRK-41.
- The nav sheet is `w-72` (`:147`) but the sidebar inside it is `w-64`, so the close X floats 32px outside the visible panel (D17).
- There is no skip link (D16).

**Findings covered:** PH-08, INV-10, D13, D09, APT-16, PH-25, D17, D18 (and D16 as a graft).

**Acceptance criteria:** see `problems.md §VX-06`, criteria 1–6.

## Options considered

**A — Minimal.**
- Add `relative` to `main` and `overflow-hidden` to the shell root, using `h-dvh`.
- Move the sidebar and header breakpoint from `md` to `lg`.
- Make the sheet `w-64`.

*After:* the document never scrolls and tablets get the full width. But from 768 to 1023 users get the stripped mobile bar with no search, bell or settings, so criterion 2 fails.

**B — Restructure: three sidebar modes.**
- The shell becomes `grid h-dvh grid-cols-[auto_1fr] grid-rows-[auto_1fr] overflow-hidden`.
- The sidebar has three modes: full (≥1280, `w-64`), an icon rail (768–1279, `w-16`, with tooltips and expand on demand) and a sheet (<768).
- The header stays responsive:
  - Search collapses to an icon below 1024.
  - The Branded toggle and Start Tour move into an overflow menu below 1280.
  - Bell and settings are visible everywhere.
- `main` is the only scroller.

**C — Convention: a persistent sidebar on large screens and an overlay sidebar below, with one header everywhere.**
- Jira, Notion, Linear and Gmail on narrow windows hide the sidebar behind a menu button. They keep the same header at every width, collapse search to an icon or command palette on narrow widths, and move account and utility toggles into a menu.
- C means: ≥1024 persistent sidebar; <1024 an overlay `Sheet`.
- One `Header` component at all widths:
  - a menu button below `lg`;
  - search becomes an icon below `md`;
  - the Branded toggle and Start Tour go into a "More" menu below `xl`;
  - bell and settings are always visible.
- Plus A's containment.

## Scores
Max 60. Compressed run: one agent scored from each lens; no external judges.

| Option | Usability | Visual craft | Engineering |
|---|---|---|---|
| A Minimal | 44 (**fails criteria 2 and 4**: no search or bell below 1024) | 44 | 46 |
| B Restructure (rail) | 47 | 49 | 40 (icon rail, tooltips, collapse persistence, 3 modes to test) |
| **C Convention (overlay + unified header)** | **52** | **52** | **52** |

A is disqualified because B and C both pass. Between B and C:
- The rail keeps navigation one tap away, but on a 768 portrait tablet (common at clinic front desks) it permanently takes 64px from the work area.
- With about nine nav items, two taps through an overlay is fine.
- C also removes the separate mobile bar, so there is one header to maintain instead of two.

## Decision
**C, which includes A's containment fix.**

1. **`dashboard-layout.tsx`**
   - `:116`: `h-screen flex bg-gray-50` becomes `flex h-dvh overflow-hidden bg-gray-50`.
   - `:118`: `hidden shrink-0 md:block` becomes `hidden shrink-0 lg:block`.
   - `:131-156`: delete the md split and the separate mobile bar. Render `<Header onOpenNavigation={() => setNavigationOpen(true)} />` at all widths, and keep the `Sheet` state here.
   - `:159`: `main` becomes `relative min-h-0 min-w-0 flex-1 overflow-auto p-4 md:p-6`, with `id="main-content"` and `tabIndex={-1}`. `relative` makes `main` the containing block for stray absolute or `.sr-only` descendants, so they scroll and clip with it. This fixes the whole class of leak at the root rather than touching `tabs.tsx:179` and `WorkflowDocumentEditor.tsx:1084` one by one.
   - Add a skip link as the first child: `<a href="#main-content" className="sr-only focus:not-sr-only focus:absolute focus:left-2 focus:top-2 focus:z-50 …">Skip to main content</a>` (D16 graft).
2. **New `components/ui/sheet.tsx`**: a Radix Dialog with `side="left"` and `w-64 h-dvh`, whose close button lives inside the panel's header row. The mobile nav uses it instead of a restyled `DialogContent` (this also unblocks VX-02's size tokens). The panel width equals the sidebar width (`w-64`), which fixes D17.
3. **`header.tsx`**
   - `:493`: `justify-between px-6` becomes `gap-3 px-4 lg:px-6`.
   - Add a menu `Button size="icon" className="lg:hidden" aria-label="Open navigation"` as the first item.
   - Search (`:496`): `hidden md:block flex-1 min-w-48 max-w-md`. Below `md`, show an icon button (`aria-label="Search"`) that opens the existing search results in a `Dialog` (`size="lg"`, full-screen on compact per VX-02).
   - Right cluster (`:597-611`): the Receptionist tour and the Branded toggle get `hidden xl:flex`. Below `xl`, a `DropdownMenu` "More" (`MoreHorizontal`, `aria-label="More options"`) holds "Start tour" and a "Branded mode" checkbox item.
   - Bell and settings are always visible. Fix the bell's accessible name (D14 graft): `aria-label={`Notifications, ${n} unread`}`.
4. **Sidebar footer** (`sidebar.tsx:~292`): the user-name block gets `truncate` with `title` set to the full name (D18).

## Why this is the best
- **Against A:** A fixes the scroll leak, which is the most visible symptom, but makes tablets worse: search, bell and settings disappear across 768–1023. That violates I6 (recognition over recall) and P1 (category convention).
- **Against B:** an icon rail is a fine pattern, but it needs icon-only nav with tooltips, a persisted collapsed state and a third layout mode to verify. That cost is hard to justify for a nine-item nav on tablets, where full content width is worth more.
- **Norms satisfied:**
  - L1 (app surfaces don't page-scroll; only `main` scrolls)
  - L5 (no shift when menus open)
  - L6 (reflow at 768, no wrapped header controls)
  - L7 (navigation predictable, same header everywhere)
  - I7 (skip link, labelled bell)
  - P1 (Jira, Notion and Linear shell behaviour)
- **Costs and what it rules out:** between 1024 and 1279 the sidebar still takes 256px. That is acceptable, since content keeps ≥768px. Tablets need one more tap to reach nav. A dashboard page can no longer make the *document* scroll; anything that needs full-page scroll must scroll `main`.

## Implementation plan
1. Containment: the root `overflow-hidden h-dvh` and `relative` on `main`, plus a test. Ship it first; it's tiny and independent.
2. `sheet.tsx` and the nav sheet swap.
3. The unified header: menu button, search icon/dialog, "More" menu, bell label.
4. The skip link and the sidebar footer truncation.
5. Re-capture Phase 2 states at 1440, 1024, 768 and 375 on all six audited pages.

VX-01 lands in the same window ("Start Tour" single-line). `header.tsx` changes must be sequential with any VX-08 header work.

## Test plan
**Unit (RTL):**
- `DashboardLayout` renders the root with `overflow-hidden` and `main` with `relative` and `id="main-content"`.
- The first focusable element is "Skip to main content".
- At `matchMedia` <1024, the header renders a button named "Open navigation".

**Browser** (synthetic fixtures; routes: `/dashboard`, patients, appointments, visits, `pharmacy?section=desk|counter|billing`, `inventory?area=today|stock|reorder`; viewports 1440×900, 1024×768, 768×1024, 375×812):

```js
// criterion 1: the document never scrolls
await page.evaluate(() => { document.querySelector('main').scrollTo(0, 1e6); window.scrollTo(0, 1e6); });
expect(await page.evaluate(() => document.scrollingElement.scrollTop)).toBe(0);
expect(await page.evaluate(() => document.scrollingElement.scrollHeight)).toBeLessThanOrEqual(await page.evaluate(() => innerHeight));
// criterion 2 (768)
expect(await page.$eval('main', m => m.getBoundingClientRect().width)).toBeGreaterThanOrEqual(720);
const hdr = await page.$$eval('header button, header [role=switch]', bs => bs.map(b => b.getBoundingClientRect().height));
expect(Math.max(...hdr)).toBeLessThanOrEqual(40);
for (const name of ['Search', 'Open settings']) expect(await page.$(`header [aria-label="${name}"]`)).not.toBeNull();
expect(await page.$('header [aria-label^="Notifications"]')).not.toBeNull();
// criterion 4 (375): the nav close control sits inside the sheet
await page.click('[aria-label="Open navigation"]');
const [sheet, close] = await page.$$eval('[data-slot=sheet-content],[data-slot=sheet-close]', e => e.map(x => x.getBoundingClientRect().toJSON()));
expect(close.right).toBeLessThanOrEqual(sheet.right);
// criterion 5: opening notifications doesn't move main
const y0 = await page.$eval('main', m => m.getBoundingClientRect().top);
await page.click('header [aria-label^="Notifications"]');
expect(await page.$eval('main', m => m.getBoundingClientRect().top)).toBe(y0);
```

The Billing and Reorder checks fail today (pageScrollY 476 and 1380) and must pass after the change.
