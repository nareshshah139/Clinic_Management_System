# VX-01: Design-system controls break labels mid-word

## Problem
**Root cause.** Five shared primitives carry `min-w-0 … whitespace-normal [overflow-wrap:anywhere]`:
- `frontend/src/components/ui/button.tsx:8`
- `badge.tsx:8`
- `select.tsx:45`
- `tabs.tsx:122` (`TabsTrigger`; `TabsList` also has `flex-wrap`, tabs.tsx:101)
- `page-header.tsx:17`

They came in with commit `c8bbe35` (#33), together with the `@cc` contracts `wrapping-button-label`, `wrapping-badge-label` and `wrapping-select-value`.

`overflow-wrap:anywhere` counts break opportunities **inside words** when the browser computes min-content width, so each control's minimum width drops to about one glyph. `min-w-0` removes the flex minimum too. Tables (auto layout) and flex rows then shrink these controls to that width. The contract was meant to stop clipping. What happens instead is "Vi/e/w", "FEM/ALE", "Avai/labl/e", "IN PROGRES S", "Rem/ove", "Pen/ding".

**Findings covered:** P01, P02, D10, APT-05, VIS-05, VIS-06, VIS-16, PH-10, PH-11, PH-14, PH-27, INV-02, INV-14. It also contributes to D09, APT-16, PH-02, PH-09 and P21.

**Evidence:**
- Patients rows are 783px at 1440, 768 and 375. The Actions column is 96px and its buttons are 64×71–162 (`pages/patients/audit.json → notes.table-1440`).
- Inventory Stock rows are 190px (445 at 375).
- Header "Start Tour" takes 3–4 lines at 768.

**Acceptance criteria:** see `problems.md §VX-01`, criteria 1–5.

## Options considered

**A — Minimal: soften the wrap rule.** In the five primitives, replace `[overflow-wrap:anywhere]` with `[overflow-wrap:break-word]` and drop `min-w-0`, keeping `whitespace-normal max-w-full`. Min-content then becomes the longest word, so labels wrap only between words and break inside a word only as a last resort. The contract wording ("wrap within available width") survives.
*Before/after:* "Vi/e/w" becomes "View"; "Link Portal" becomes two lines; "Start Tour" at 768 becomes two lines.
*Risk:* controls in cramped places still turn into two- or three-line blobs, and the header still overflows its 64px row.

**B — Restructure: single-line by default, wrapping as an explicit opt-in.**
- Buttons, badges, tabs and select values render on one line (`whitespace-nowrap`). A button whose label is a sentence (quick-pick chips, long menu-like actions) opts in with `wrap`, which uses `whitespace-normal [overflow-wrap:break-word] text-left`.
- Select values truncate with an ellipsis; the full text is visible in the open list.
- When a control can't fit, the layout must deal with it (VX-03, VX-06, VX-08) instead of the control deforming.
- The `@cc` contracts are rewritten to say exactly this.

**C — Convention.** This is what GitHub Primer, Shopify Polaris, Atlassian and Material 3 do:
- Buttons, tabs and badges are single-line and never wrap.
- When space runs out, actions collapse into an overflow ("More actions") menu: Primer ActionBar, Polaris Page `secondaryActions`, the Material top-app-bar overflow.
- Tab rows scroll horizontally or collapse into "More": Material scrollable tabs, Primer UnderlineNav.
- Select triggers truncate.

C is B plus overflow menus at every crowded call site, so it is the largest change.

## Decision
**B, with two grafts from C and A's `break-word` as the opt-in.**

1. `components/ui/button.tsx:8`
   - Base: remove `min-w-0 max-w-full whitespace-normal [overflow-wrap:anywhere]` and add `whitespace-nowrap shrink-0`.
   - Keep `h-auto min-h-*` on the sizes so the app's +0.125rem text increase (`frontend/src/app/CONTRACTS`, `app-screen-text-increase`) still grows the height.
   - Add the cva variant `wrap: { true: "whitespace-normal [overflow-wrap:break-word] text-left shrink min-w-0", false: "" }`, defaulting to `false`, and expose it as a `wrap?: boolean` prop.
2. `components/ui/badge.tsx:8`: replace `min-w-0 max-w-full whitespace-normal [overflow-wrap:anywhere]` with `max-w-full whitespace-nowrap shrink-0`. Status labels become short once VX-11 lands.
3. `components/ui/select.tsx:45` (`SelectTrigger`):
   - Remove `min-w-0`, `whitespace-normal` and `[overflow-wrap:anywhere]`; add `whitespace-nowrap`.
   - Replace `*:data-[slot=select-value]:block` with `*:data-[slot=select-value]:truncate`.
   - Keep `max-w-full`. The flex automatic minimum is clamped by the definite max size, so the trigger shrinks only to its container and then truncates.
4. `components/ui/tabs.tsx`
   - `TabsTrigger` (:122): replace `min-w-0 … whitespace-normal [overflow-wrap:anywhere]` with `shrink-0 whitespace-nowrap`.
   - `TabsList` (:101): replace `flex-wrap justify-center` with `justify-start overflow-x-auto [scrollbar-width:thin]`. This is the graft from C: Material-style scrollable tabs.
   - `@cc scaled-tab-text` is unaffected.
5. `components/ui/page-header.tsx:17`: `[overflow-wrap:anywhere]` becomes `[overflow-wrap:break-word]`, so titles may wrap, but only between words.
6. Contracts: rewrite the three `@cc wrapping-*` blocks.
   - Button: "Text buttons MUST render their label on one line by default and MUST NOT break inside a word. A button that must hold a sentence opts in with `wrap`, which wraps only between words. Icon buttons MUST keep their square size."
   - Badge: the same, without the opt-in.
   - Select: "Selected labels MUST stay on one line and truncate with an ellipsis inside the trigger without hiding the indicator; the full label MUST be visible in the open list."
   - **The owner (nareshshah139) must approve before merge.**
7. Call-site sweep (implementation step): run the label audit below, then add `wrap` only where the label is a phrase that is meant to wrap, for example the `PrescriptionBuilder.tsx` quick-pick buttons (~:5060-5067). Nowhere else.
8. Graft from C, scheduled with VX-08: the patients row actions (`PatientsManagement.tsx:1169-1182`) move to one primary action plus a "More" `DropdownMenu`. That is what brings rows down to ≤56px.

## Why this is the best
- **Against A:** A stops letter-level breaks but keeps the cause of the ugliness, which is controls that change height to absorb layout pressure. "Start Tour" would still be two lines in a 64px header, and table rows would still stack two-line buttons. The norms say labels are single-line and the *layout* reflows (L6, H5, P2). Under A the control reflows instead.
- **Against C:** C's overflow menus are the right end state for crowded rows. Doing them here would turn an S-effort P0 fix into an M/L redesign across every table and toolbar. Grafting only the tab-scroll part keeps this cluster at the primitive level.
- **Norms satisfied:** L6 (reflow, not overflow), H5 (one look per control), I1 (a button reads as a button), C4 (truncation shows the full text on open), A4 (labels still enlarge with text size).
- **Costs and what it rules out:** where a layout was silently squeezing controls, it will now overflow visibly (Desk Manual Daily Entry, the 768 header). That is intended, because the geometry audit can then catch it, and VX-03 and VX-06 remove those overflows. Multi-line buttons become a deliberate, rare choice, and the contract change needs owner approval.

## Implementation plan
1. Primitives (`button`, `badge`, `select`, `tabs`, `page-header`) and the contract text, in one commit.
2. Run the label audit at 1440, 768 and 375 on the six audited pages and on `/dashboard/rooms`, `/dashboard/users` and `/dashboard/pharmacy/invoices`. List every control whose height exceeds its single-line height or whose box overflows its parent.
3. Fix each overflow at its layout (VX-03 or VX-06 owns most of them), or add `wrap` if the label really is a sentence.
4. No page-level ad-hoc `whitespace-*` overrides on these primitives.
