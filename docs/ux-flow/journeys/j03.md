## What a doctor must actually do (the 80% gate), measured

The discovery document says completion is blocked below 80%. On the live app, progress is `completedSections / 5` and a doctor can only ever mark four sections: vitals, photos, labs, prescription (`MedicalVisitForm.tsx:793`). So "80%" means all four. Measured minimum:

- Prescription: "Create Prescription" marks it (20%). Screenshot `07-go-to-pharmacy-dialog.png` shows "Progress: 20% . 1 of 5".
- Vitals: "Mark Vitals Complete" counts with every field empty (60% after labs, `09-lab-tests-tab.png` shows the green dot on Vitals). Measured.
- Labs: "Save Labs" counts with nothing ticked. Measured.
- Photos: the only section that cannot be satisfied with an empty click. At least one real photo must be uploaded (`MedicalVisitForm.tsx:1511-1522`, the photo count effect). Without it "Complete Visit" stays disabled at 60% (`10-photos-tab.png`, footer "Remaining: photos"). Measured.

The script does exactly that and nothing else. Note the gate is 3 empty-click "attestations" plus one forced file upload: it checks nothing clinical (the page itself says "Section progress does not verify clinical completeness"). Completion succeeded with vitals null in the saved visit (measured through `/api/visits`).

Two routes to start exist and the screen pushes the calendar START button hardest, so that is scripted. Others (patient list "Start Visit", patient detail, header notification, Visits setup) are described in `docs/ux-paths/topics/doctor-visit.md`. Hover is free in this harness, so the hover that reveals START (`CalendarColumn.tsx:300`, `opacity-0` until row hover or focus) is not counted; a touch or keyboard user cannot reveal it that way (suspected).

## 3. The Simpler Version

1. Dashboard shows "Next patient: Vikram Patil, 11:30" with one button "Start visit" (or the calendar column is first and each confirmed row shows a visible "Start").
2. The visit opens directly on the prescription page, with patient, allergy and last diagnosis in a slim header.
3. Type the chief complaint.
4. Type the diagnosis.
5. Type the first medicine and pick it; frequency and duration are pre-filled from the doctor's last use of that drug (or a sensible default) and the instruction field is editable inline.
6. Type the second medicine and pick it; adjust the duration if the default is wrong.
7. Press "Complete visit". It saves the prescription, marks everything required, and returns to the day's list with the next patient highlighted. Photos, vitals and labs are optional and never block completion.

Nine actions, no dialogs.

## 4. Clarity Issues

- "Create Prescription" vs "Print Preview" vs "Print" vs "Save Draft" vs "Complete Visit" vs the preview dialog's "Save Prescription": six ways to finish something. Which one makes the prescription visible to the pharmacy is not clear from labels (measured: Create Prescription).
- "Mark Vitals Complete" and "Save Labs" suggest the doctor must record vitals and labs; they accept empty input (measured, `08`, `09`).
- "Complete Visit" is disabled with the reason far from the button and in terms of "sections" a doctor never sees listed (`MedicalVisitForm.tsx:2715`). The listed "Remaining: vitals, photos, labs" reads as clinical content missing.
- Patient is "Patient Context" in the sidebar, "Patient:" in the identity line, and Visit #2 / "Visit Documentation" in headings; the page calls itself "Visit Documentation", "Medical Visit Documentation" and "Visits" in the menu.
- "Frequency" shows "1-0-1" (a dose pattern) for what the calendar and pharmacy call "twice daily"; "0-1-0" is not "night" anywhere on screen. The "HS" preset sets once daily but does not say night.
- Row label "When" has no value to pick in this journey and is empty on both medicines.
- Calendar: the "START" button and the "INFO", "RESCHED" buttons are all-caps, equal, and hidden. The tooltip names are "Start Visit"/"Continue Visit", the button text "START"/"CONT".
- The two photo tabs say "Before / After Photos" while the journey only needs a photo of the lesion.
- Calendar button text "CONT" (for continue) is an abbreviation.

## 7. Verdict

Convoluted.

Reasons, measured: 26 actions against an honest minimum of 9 (17 extra); the three largest costs are non-clinical (seven completion-ritual actions, three prescription plumbing actions, three per-medicine preset clicks); one forced file upload with a dialog; one dialog that guards nothing; a calendar whose primary button is hidden and below the fold; a form that opens on the wrong tab; and a dead end after the last click. Several screens fail three or more heuristics at once (the calendar, the visit shell, the prescription builder: take-away, one primary action, once and only once). For a loop run 30 to 60 times a day, the 17 extra actions are roughly 500 to 1000 avoidable clicks per doctor per day.

Functional note (one line): "Complete Visit" succeeded and stored `vitals: null` (measured via `/api/visits`), so the 80% gate does not protect data quality.
