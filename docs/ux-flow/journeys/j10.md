## 3. The Simpler Version

1. Inventory, then "Receive delivery" (one visible button; "Scan a photo" is the second).
2. Pick the supplier (preselected if the last one is likely). Name, GSTIN and licence fill themselves.
3. Type the bill number. Dates default to today.
4. Type the item name; pick Tretinoin Cream from the suggestions. Product, pack, unit, MRP, GST and HSN fill from the item.
5. Type batch, expiry as `10/2028`, quantity 20, rate 92.
6. "Add stock". The result says "20 added to Tretinoin Cream (now 23)" with "Enter another bill" and "Pay this bill".

About 11 actions, 0 detours, 0 forced matching steps.

## 4. Clarity Issues

- "Distributor" (field), "Supplier" (section title, select label, route name) are the same concept on one screen. Pick "Supplier" (matches Suppliers, Supplier returns elsewhere in Inventory).
- "Scan or enter bill" is the menu name, "Receive" is never used; the page title "Inventory" says "Receive, review and manage"; the commit button says "add stock"; the result says "Stock added"; the register says "Post bill". Three verbs for one act. (measured)
- "Type instead" assumes the user knows what the alternative to typing is ("instead of" what is on another half of the card).
- "Not in inventory" shown for a product that is in inventory (measured, `05`): it means "no exact pack match". Say "No exact match for this pack".
- Pack Size is overwritten silently after a match (`08`: `20g` became `1 unit`); Pack in the matching card vs Pack Size in the line vs Stock unit: three names for pack/unit.
- "Needs correction" red badge appears on never-edited blank fields; it reads like the user did something wrong.
- "Confirm this match" vs "Confirm Match" vs "Match <name>": three labels for the same decision.
- "Confirm reviewed values & add stock": says "reviewed" though nobody reviewed; it is "Add stock".
- HSN, DL No., CGST/SGST/IGST: accounting codes the pharmacist should not need to retype; at minimum, one "GST 12%" field.
- Stock list API row `currentStock` is per batch; a received batch is a new row, so the screen total of a medicine is the sum of batches. Not a defect, but "stock went up by 20" is visible only by summing.

## 7. Verdict

**Convoluted.** 10 extra actions over an 11-action ideal; the app asks for six things it already knows (licence, HSN, MRP, pack, unit, product name twice); a product-match ritual of four controls for an item that exists; three blockers shown before any input; and a "Type instead" link as the entry to the route the pharmacist actually needs without a scan. The route does complete, and there is no approval stage for a pharmacist, which is its saving grace.
