### Decision points (10; 5 needless)
1. **Add manual request (primary) vs Sync shortages (secondary)** (needless as styled). The routine weekly action is the secondary button (02).
2. **Which Supplier select to use**: header form "Supplier · Select supplier" *or* bottom "Supplier recommendation · Select a saved supplier + Save supplier" (needless). These are two controls for one field on one screen. Choosing the bottom one leaves the top one empty (j6d log: header value `""` after Save supplier).
3. **Save draft vs Create purchase order** (needless; conversion saves).
4. **Save draft vs Submit for approval** (needless; Submit also saves, as the revision 2 and 3 SAVE entries show).
5. **Submit, then Approve, as the same approver** (needless for an approver). It costs two clicks and a status hop with no second person. Non-approvers still need the split.
6. Quantity, expected date and priority on the PO (valid).
7. **Send purchase order vs Export** (needless while mail isn't configured). "Send" always fails into SETUP_REQUIRED (14).
8. **Which receiving route**: **Receive remaining stock**, **Review linked receipts**, or Purchases → Inward challans → New + "Purchase order" select + per-line "Match order line" (valid alternates, but three of them; the prefilled one is best).
9. **Cancel document vs Cancel remaining quantities** (valid but a trap: Cancel document fails once there are receipts, per the story's Edge Cases). Only the valid one should show.
10. Received quantity (valid).

### Re-entry
1. **Supplier**: chosen and saved at the bottom of the shortbook doc, but not reflected in the header Supplier field until a reload (06 vs 08). That leads straight to Re-entry 2.
2. **Reload after your own save**: the user must press **Reload saved record** (or refresh) to continue after their own Save supplier (07). The app already knows the new version.
3. **Batch and expiry can't be entered at receipt** (structural; measured in the UI, the detour itself is suspected). The challan line shows batch/expiry read-only ("— · STRIPS", 15-challan-scroll-1). The "Add a batch" search only finds existing batches, and when there is no match the editor says *"No matching batch. Add the product/batch in Stock, then return here."* (`WorkflowDocumentEditor.tsx:1074`). The receipt in this walk posted **+20 with no batch and no expiry** (16). Recording "IS2611 / 2028-04-30" as the story asks means a detour to Stock → Add batch. That form has no batch or expiry fields (ux-visual INV-06). This is also why every stock row reads "expiry unverified · Batch missing" (INV-04).

### Dead ends (4)
1. **After Approve**, the sticky header (status + primary action) is empty (12-po-approved). The next actions, **Receive remaining stock** and **Send purchase order**, sit below the form, the line table and the document history.
2. **Send purchase order** with no mail transport: the button can only fail. Its result is a status line and a log entry; the actual delivery action is an unlabeled icon (14, 18).
3. **Today "Low stock" (6)** goes to Stock list `?stock=LOW` with no "Add to shortbook" or "Reorder" action (24). The user must return to Reorder → Sync.
4. **After Cancel remaining units**, the page still says **"Part received … receive only the outstanding goods through another linked inward challan"** until a reload, which then shows **Cancelled** (20 vs 22). The guidance contradicts what the user just did.

### Hesitations (7)
- **Absurd sync quantities**: items with the default max 500 produce "Wood's Lamp (Dermatology): **498 PIECES**", "Dermatoscope: 499 PIECES" and "Electrocautery Tips: 495 PACKS". Sync can't be trusted without opening each request (03, 04).
- **Raw IDs**: "Requested by cmw6d94az00017dw06nw9bzrl" on every row; "Supplier cmw6fgf4k00gz7dc1508lnk96" and "Min See item / available See item" on the closed request; history lines "cmw6d94az… · CREATE" (04, 05-scroll-2, j6j log).
- **Truncated references** used as page titles: "PO-NEED-2026-11-07-Isotretinoin 20 mg Capsules (Strip of 10" is cut mid-parenthesis (08, 12). The CSV is named the same.
- **Narrow inputs**: Rate excl. GST and GST % render "19" and "1:" (11-po-submitted, 05-scroll-1).

## Take-away Pass

### Shortbook list (02, 03, 04)
| Element | Removable? | Action |
|---|---|---|
| Filter block (Search, Status with 12 options, Supplier GSTIN, From, Through, Apply, Clear) above the results | Deferrable. With 8 rows it pushes the list to y≈640. | Collapse to a search box + "Filters" |
| Orphan export icon under the filters | Keep, but label it ("Download lines") | Label |
| "· all result pages included" | Yes | Remove |
| Per row: reference "NEED-2026-11-07-<item>" **and** "<item>: 40 STRIPS" | Item name twice per row | Show item, qty, supplier; demote the reference |
| "LOW_STOCK · NORMAL · date · Requested by <id>" | Raw enums and ID | "Below minimum · requested by Admin" |
| "Draft • no stock change" on every row | Mostly; it's true of every shortbook row by definition | Show the status only when it isn't Draft |

**One primary action?** In Draft: yes (Submit for approval). After **Approved**: **none in the header**, and the primary **Receive remaining stock** sits below the fold (12 vs 18). Visual weight doesn't follow the next step.

### Inward challan (15, 16)
- **Purchase order select (prefilled) and per-line "Match order line" select (prefilled)**: the user arrived from the PO, so both are already known. Make them read-only.
- **Date**: left empty (mm/dd/yyyy). Default it to today.
- **Free / Discount % / Scheme ₹ / Rate / GST % columns at receipt time**: these are for the bill, not the receipt. Hide them on a PO-linked challan.
- **Batch / Expiry**: these are **missing** and needed. Add them, as this is the one place they should be captured.

## The Simpler Version

Same goal, same controls (approval for non-approvers, reason on cancel, audit history kept but collapsed).

1. **Inventory → Reorder.** The shortbook is fresh: it syncs on open, or **Sync shortages** is the primary button. It is grouped **by supplier**, one row per item: "Isotretinoin 20 mg — 60 on hand / min 70 — order 40 strips — Sai Balaji (last used)". The Today "Low stock" row links here too.
2. Tick **Isotretinoin** and **Itraconazole** under Sai Balaji. The supplier is prefilled from the item's last or only saved supplier, with an inline change dropdown.
3. Click **Create PO**. One PO opens with both lines.
4. Edit the quantity to 30, set Expected 10 Nov (defaulted from supplier lead time) and Priority HIGH.
5. Click **Place order**. For an approver this submits and approves in one step, with history recording both. A non-approver sees **Request approval** instead.
6. The header's primary becomes **Share order**: CSV / WhatsApp text, or email when configured.
7. **Delivery day**: Today → **Orders awaiting receipt (1)** → PO → **Receive**. An inline receipt opens on the PO with ordered/remaining shown and editable fields: received qty **20**, batch **IS2611**, expiry **2028-04-30**, date defaulted to today.
8. Click **Post receipt**. The header now offers **Receive more** / **Close remaining (10)**.
9. Click **Close remaining**, enter the reason "Distributor out of stock till Dec", and confirm. The PO shows **Closed — 20 of 30 received**, and the shortbook request shows **Fulfilled (partial)**.

That is about 14 interactions for one item, including batch and expiry capture. The current flow takes 26 and captures neither. **This saves about 12 interactions, removes 1 forced reload, 1 always-failing button and 1 tab jump, and fixes the missing batch/expiry data at its source.**

### Concrete changes
1. **One supplier field** on the shortbook document. Delete the bottom "Supplier recommendation" select and the **Save supplier** button; show the recommendation as option hints. Saving the supplier must not invalidate the open form (no "document changed, reload" after your own save).
2. **Batch shortbook lines, not documents.** One shortbook per branch (or per supplier) with lines and checkboxes, so one PO can cover several items. Today each shortage is its own `NEED-<date>-<item>` document, and the story's own ideal count "grows per item".
3. **Make Sync the primary** on the Shortbook; demote **Add manual request**. Cap order-up-to quantities when max is a placeholder default (500), or flag "no real max set" instead of proposing 498 units.
4. **Drop the separate Save draft before Submit** (Submit saves). **Combine Submit + Approve for approvers** into "Place order", keeping both history entries.
5. **Status-driven sticky header**: Approved → "Receive" + "Share order"; Part received → "Receive more" + "Close remaining"; Closed → "Reorder again". Move these out from below the document history.
6. **Hide "Send purchase order" until mail transport is configured.** Promote **Export / Share order** to a labeled button.
7. **Receive on the PO itself**, as an inline receipt panel that posts an inward challan behind the scenes. Do not jump to the Purchases tab. Keep the Purchases → Inward challans route for unplanned deliveries.
8. **Capture batch and expiry on the receipt line**, creating the batch if it's new. Default the receipt date to today. Hide bill-only columns (Free, Scheme, Discount, GST) on a PO-linked receipt.
9. **Show only the valid cancel**: hide **Cancel document** once receipts exist and show **Close remaining** instead. Refresh the status panel after the action.
10. **Today "Low stock" row → Reorder shortbook**, filtered to those items, with an "Order" action. Not the Stock list.
11. **Hide the recovery panel and handoff textarea on the happy path.** Show them only on an actual error or permission denial.
12. **Name people and suppliers, not IDs.** Use short references (e.g. `PO-0007 · Isotretinoin 20 mg`), not truncated item names.

## Clarity Issues

| Label / copy | Problem | Suggested |
|---|---|---|
| **"Shortbook"** | Trade term. It's fine for Indian pharmacists, but the app also says "request", "demand", "need" and "NEED-…". | Pick one: "Shortbook" for the list, "item" for its lines |
| **"Sync shortages"** | Doesn't say what happens | "Add items below minimum" |
| **"Requested by cmw6d94az00017dw06nw9bzrl"**, "Supplier cmw6fgf4k…", history "cmw6d94az… · CREATE" | Raw IDs (also catalogued in the story's Defects) | User and supplier names |
| **"LOW_STOCK · NORMAL"**, **"Draft • no stock change"**, **"SETUP_REQUIRED"**, **"PART_RECEIVED"** | Raw enums | "Below minimum · Normal priority", "Draft", "Email not set up", "Part received" |
| **"Min See item / available See item"** | Placeholder text shown as data | Show the numbers or omit |
| **"Recovery handoff"** textarea, **"Reload saved record"** | Engineering vocabulary on a normal screen | Only on conflict: "Someone (or you) changed this. Refresh to continue." |
| **"This document is a draft. Review its details and the available recovery actions."** | Implies something went wrong | Remove on the happy path |
| **"Approve document"**, **"Cancel document"** | "Document" is generic, and the page is a purchase order | "Approve order", "Cancel order" |
| **"Receive remaining stock"** before anything has been received | "Remaining" is odd for the first delivery | "Receive delivery" |
| **"Inward challans"** | Correct Indian term, but it is the receipt for the PO the user is on, and the tab switches to "Purchases" | "Receipt for PO-…" in the Reorder context |
| **"Cancel remaining quantities" / "Cancel remaining units"** | Two phrasings for one action | "Close remaining (10)" |
| **Shortbook status "Cancelled"** after 20 of 30 received | Reads as nothing happened | "Closed · 20 of 30 received" |
| **"Add a batch"** on a demand note | It searches existing products and batches; it doesn't add a batch | "Add item" |
| **"Monitor"** hidden in a "More tasks…" `<select>` | A navigation menu built from a form control | Tabs or a menu button |
