## 2. Take-away Pass

**Dashboard landing (`01-dashboard.png`)**: not part of the work. The receptionist's first action is always "Appointments". Welcome sentence, "Important notifications requiring your attention" and "Upcoming appointments for today" restate their headings. Four stat cards (Total Users, Active Users, Total Branches, System Status) mean nothing at the front desk. The quick-guide and tour buttons are extra chrome. Primary action: none; the sidebar is the only way forward. Ideal: land on Appointments for RECEPTION (a one-line redirect), which removes action 1 from every front-desk journey.

**Appointments page, before any input (`02-calendar-today.png`)**: removable now:

- The empty card padding above Doctor and Date (about 40px).
- Visit Type, Room and Grid filters: used for nothing on this journey; they are a view setting, not a booking step. Defer behind a "Filters" disclosure.

The OPD/Procedure/Telemedicine/Completed/Past/Newly Booked/Booking In Progress swatches explain colours a user can read off the rows (the rows already carry "Review", "First", status dot).

- Exactly one primary action? No. The first thing in the eye line is a date picker, a doctor select and a Quick Guide button of the same visual weight; the patient field, the real first step, is a small input half-hidden on the fourth row ("Search patient by nam", truncated).

**Patient search (`04-patient-selected.png`)**: the patient is shown three times (input text, "Selected:" chip, later the dialog). The amber "Select a patient from the list..." strip and the "Tip: enter patient name and phone..." line appear while the result list is already visible. ## 3. The Simpler Version

1. Sign in: receptionist lands on Appointments (no dashboard hop).
2. Click "Tomorrow" (or pick the date). Doctor is already Priya Menon.
3. Type "Kavita" in the Patient box, which sits first in the toolbar and is wide enough to read. One match: it is selected automatically; several: click one.
4. The calendar is already in view (no Legend). Click the free 10:30 tile (15-minute gaps clickable at any grid). Booking is made at once with OPD, tile length and no room. A toast reads "Booked: Kavita Naik, 14 Nov 10:30. Change details | Undo".

Actions: menu skipped (0), date 1, type 1, tile 1 = 3 to 4. A call where the patient is not on the first match adds 1.

## 4. Clarity Issues

- "Scheduled" and "Confirmed" are the app's own vocabulary: a booking made on a live phone call with the patient's agreement is "Confirmed", yet the column described as "Booked ahead" is the one named for future bookings. The user guesses (suspected; `appointment-calendars.ts:17-31`). Heading wording "Confirmed, walk-ins and visits." mixes three ideas.
- Date field shows `11/14/2026` (US order) in a clinic in India, while the dialog shows `14 Nov 2026` (`02-calendar-today.png` versus `05-booking-dialog.png`; measured in an en-IN browser). One format everywhere.
- "Slots" tab next to "Calendar": two tabs for the same job (booking), measured as present, not used. Story file says both open the same dialog.
- "Grid" (a time-step filter) and "Visit Type" filter share the toolbar with the Patient box, so a booking input and view filters look alike. "Visit Type" in the filter, "Appointment Type" in the dialog, "(OPD)" in the banner, "Review"/"First" on rows: four names for related ideas.
- Dialog helper "Room selection is optional for opd appointments" shows the code in lowercase (`AppointmentBookingDialog.tsx:426`).
- Room cards wrap the "Available" badge letter by letter at a 4xl dialog (`05-booking-dialog.png`).
- Row hover buttons INFO / RESCHED / START: abbreviations a non-computer person must learn (not on this path).
- The search placeholder "Search patient by name/phone" is cut to "Search patient by nam".

## 7. Verdict

**Acceptable.** Six actions against an ideal of five, with no dead end and sensible defaults for doctor, type, duration and room. The friction is not in the steps. It is in the screen around them: a Legend card that pushes the calendar below the fold, the same Scheduled/Confirmed explanation three times, a dialog that asks nothing a plain visit needs, and a 30-minute grid that hides the true first free time. The calendar screen on its own fails three heuristics (take-away, once-and-only-once, progressive disclosure), so the clean-up is worth doing for the single most repeated front-desk task even though the step count is close to minimal.
