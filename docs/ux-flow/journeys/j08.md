## 2. Take-away Pass

### Login page (`d-login.png`, `p-login.png`)
- "Branded" switch top-right (`login/page.tsx:59-68`): nobody needs a theme switch before they have signed in. Remove from login. It is a per-browser setting (see Branded below).
- Letterhead image takes 100px of height above a heading "ClinicMS Login" (line 74): the image already says whose clinic this is; the heading restates "login" next to a "Sign in" button. Keep one.
- Password placeholder `••••••••` (line 108) makes the empty field look filled (measured, `d-login.png`: the dots are visible in the empty box). Change to empty or "Password".
- "Sign in" is disabled and grey until both fields are filled (line 113) with no reason shown. Acceptable; the error branch at line 41 is unreachable.
- Two helper sentences under the button (lines 117-118): the first restates the label, the second is the only recovery route; keep a shortened form.
- Exactly one primary action: yes. Visual weight is right.

### Dashboard (all roles)
- Four stat cards "Total Users 4 / Active Users 4 / Total Branches 1 / System Status operational" (`dashboard/page.tsx:217-238`, rendered 276-292) are seen by every role including reception and pharmacist (measured, `d-reception-dashboard.png`, `d-pharmacist-dashboard.png`). None leads to a task, none is a daily number, "Total Branches 1" never changes in a one-branch clinic. Take away for all roles; the owner may keep one line under Users.
- "System Alerts" card with always-present "System Status / All systems operational / LOW" row (`page.tsx:116-124`) states "operational" a second time (stat card says "operational" too). Remove the row.
- Alert rows look like buttons (grey rounded rows, severity badge) but are not clickable (measured: clicking "Low Stock Alert" stayed on `/dashboard` for all four roles). Rows have no link target in code (`page.tsx:358-392`).
- Severity badges HIGH/MEDIUM/LOW (line 389) next to a coloured triangle and a coloured circle: the same fact three times.
- "Today's Appointments" is the only role-relevant card for reception/owner; for the doctor it is pushed below two tall panels (`page.tsx:273` places `DoctorPatientPanels` first). Rows are plain text, no START, no click (`page.tsx:416-441`). Statuses shown raw: "IN_PROGRESS", "CONFIRMED".
- "Quick Guide" button top right of the page (lines 243-271) and "Start Tour" in the header for reception: two help systems; the guide's text describes the cards we propose removing ("View key metrics including total users...").
- Database Backup card for owner (lines 295-337): a rare admin action occupying 250px of the owner's first screen, above the alerts the owner would act on (measured `d-owner-dashboard.png`). Demote to the Users/Settings area.
- Exactly one primary action per screen: no. Reception sees none (the only button, "View All Appointments", is an outline button at the bottom of a card that starts at y=360 and spills below the 850px fold). Owner's loudest control is "Create Backup" (black).

## 3. The Simpler Version

One principle: each role lands on its own work queue; counts and links go where they promise.

**Login**
1. Letterhead image, one heading removed or kept, field "Phone or email" focused, field "Password", "Sign in". No Branded switch. One recovery line: "Forgot password? Ask your clinic admin for a reset code." with the link on "reset code". Empty password field has no dots. (`login/page.tsx`)

**Reception landing (replaces `/dashboard` content for RECEPTION)**
1. Greeting with her name ("Good morning, Sunita"), one line.
2. Three large buttons: "Book appointment", "New patient (walk-in)", "Take payment" (each one click to the dialog or screen it opens, 1 instead of the current 2).
3. "Today's appointments" list with the next patient first, each row clickable to its appointment, statuses in plain words (Waiting, With doctor, Done).
4. "Dues to collect" one line (1 overdue invoice, Rs 2,360) linking to the invoice.
5. Menu: Dashboard; Patients; Appointments; Pharmacy (a single entry: Counter) . Drop Rooms, Pharmacy Desk, Inventory from the reception menu unless a task needs them. Header: search, bell, name + "Log out". No Start Tour (move into Quick Guide), no gear, no Branded.

**Doctor landing**
1. "Today's patients", this doctor's rows first, the next one highlighted with a single "Start visit" button on each row (replaces the Appointments > START route: 2 clicks to 1).
2. "Find a patient" search box (the existing My Patients search, moved up and without the 10-row list as default).
3. Recent visits collapsed below (or in Patients).
4. No stat cards, no alerts (overdue invoices, stock are not the doctor's).
5. Menu: Dashboard; Patients; Appointments; Visits; Pharmacy Counter (if the doctor prescribes in-system). Hide: Daily Collection, Procedures (unless procedures are a clinic offering, then keep), Rooms, Pharmacy Desk, Sales, Inventory, Pharmacy Report, Test Transcribe. Gear stays (signature, letterhead, availability are real). The bell lists today's next patients ("Vikram Patil, 11:30, Start visit") and its links open the visit with the patient already selected.

**Pharmacist landing**
1. Prescription queue count and first waiting prescription with a single "Bill" button ("Meera Shah, 3 medicines, waiting 1 min": 2 or 3 clicks to 1).
2. "Walk-in bill" button.
3. "Low stock (N)" and "Expiring soon (N)" as links that open the list (fixes `tab=` to `area`/`view`).
4. No stat cards, no System Status.
5. Menu: Dashboard; Pharmacy Counter; Sales; Inventory. Pharmacy Desk, Daily Collection, Pharmacy Report: hide unless needed; Pharmacy Desk becomes a tab inside the counter or is removed from this role. No gear.

**Owner landing**
1. Row of three numbers, each a link: "Today's collection Rs 2,199" (to Daily Collection), "Dues Rs 2,360" (to Sales with `?pay=CREDIT`), "Requests to approve N" (to the approvals row in Inventory).
2. Then "Needs attention": low stock and expiring lines, now with working links.
3. Today's appointments optional, collapsed.
4. Database Backup moves to Users (or an Admin page).
5. Menu: Dashboard; Daily Collection; Patients; Appointments; Sales; Inventory; Users; Reports (monthly). Remove Test Transcribe from production; move Fee list under Users or Reports. No gear for the owner (empty), no Branded.

## 7. Verdict

**Convoluted** for the shell, minimal for the form. The sign-in page itself is three fields of work and already sensible (Enter submits, field focused, `next=` honoured, 4 actions to reach the schedule). The landing is the problem: all four roles get the same four administrator cards, none of the roles gets the task it came for within two seconds, and the pharmacist gets nothing to act on at all (measured). The menu shows 7 to 14 entries of which 2 to 6 are used daily, and the bell sends reception and the doctor to the wrong place and the pharmacist and owner to a screen that ignores its own link. Branded is a per-browser colour switch and should not sit on the working screen.
