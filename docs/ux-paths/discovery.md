# App Discovery: Linaé ClinicMS (Clinic Management System)

Generated by the ux-paths Phase 1 discovery agent (read-only scan of `frontend/`, `backend/`, `shared-types/`).
Browser title: "Linaé | Clinic Management". In-app brand: "ClinicMS" (sidebar logo, login card "ClinicMS Login").
Domain: an Indian dermatology / skin, hair and aesthetic clinic with an attached pharmacy (INR, GST, ABHA IDs, Hindi/Telugu prescriptions).

## Application Type

Authenticated, role-based **web app** (desktop-first, with a mobile hamburger drawer). No public/marketing pages; `/` redirects to `/dashboard`.

## Tech Stack

- **Frontend**: Next.js App Router (`frontend/src/app`), React client components, shadcn/Radix UI (`components/ui/*`), Tailwind, lucide icons, `recharts` (pharmacy AI dock charts), `intro.js` (guided tours), `pagedjs` (prescription print preview pagination), `html2canvas` + `jspdf` (prescription PDF), `html2pdf.js` (pharmacy invoice PDF). One env var: `NEXT_PUBLIC_API_URL`.
- **Routing guard**: `frontend/src/middleware.ts` redirects any `/dashboard/*` request with no `auth_token` cookie to `/login?next=<original path+query>` (exception: `/dashboard/appointments/google-callback`). `/test-transcribe` is outside the matcher (no middleware guard; API calls still need auth).
- **Client state**: `DashboardUserProvider` (fetches `/auth/me` then `/users/:id`; 401 → `/login`), `BrandedModeProvider` (localStorage `cms_branded_mode`, palette extracted from `/letterhead.png`), localStorage persistence of appointment doctor/date (`appointments.doctorId`, `appointments.date`), tour-seen flags, sessionStorage pharmacy checkout attempt (`pharmacy-checkout-attempt-v1`), visit drafts / autosave.
- **Backend**: NestJS + Prisma (Postgres). Global JWT cookie auth (`JwtAuthGuard`), `RolesGuard` + `PermissionsGuard`.
  - **RolesGuard: OWNER, ADMIN and DOCTOR bypass every `@Roles` check** (universal access).
  - **PermissionsGuard: OWNER always passes; ADMIN and DOCTOR bypass; others need the permission in `user.permissions` JSON ∪ their `Role.permissions`.**
  - Inventory workspace: OWNER/ADMIN/DOCTOR get `*`; approvers for workflow docs/settings = OWNER, ADMIN, MANAGER.
- **shared-types/**: DTO/type package shared by both sides.
- **Seed users** (`backend/scripts/seed.ts`, password `password123`): `admin@clinic.test` / 9000000000 (ADMIN), `shravya@clinic.test` / 9000000001 (DOCTOR), `praneeta@clinic.test` / 9000000002 (DOCTOR), `reception@clinic.test` / 9000000003 (RECEPTION); sample patient `john.doe@patient.test`.

## Feature Map

### Auth, session & shell
- Sign in with phone or email + password; `?next=` return; disabled button until both fields filled.
- Password reset via admin-issued one-time code (Users → "Reset password" → code shown once, "Copy code"; 24h expiry) → `/reset-password`.
- Logout (sidebar icon) → `/login`. 401 on `/auth/me` → `/login`.
- Branded mode toggle (login + header), palette extracted from letterhead image.
- Global search across patients (→ `/dashboard/patients?search=<id>`), appointments (→ `/dashboard/appointments`), users (→ `/dashboard/users?search=<id>`).
- Notifications bell (system alerts mapped per role).
- Database backup (ADMIN/OWNER dashboard, `POST /auth/backup` + job polling `GET /auth/backup/:jobId`).

### Patients
- List "Patient Records" with search "Search by name, phone, ABHA, or email (min 2 chars)", "Did you mean" suggestions, filters (All Genders, All Consultations / Online / Offline, Date Range All Time / Last 1 Week / Last 1 Month), Per page, "Clear Filters"; empty state "No patients found".
- "New Patient" → "Create Patient" dialog (First/Last Name, age, Gender, Phone, ABHA, Email, Address, Emergency Contact, Consultation Type, Primary Doctor (Automatic / Not assigned), source (Instagram, Twitter, Google, Doctor, Friends & Family), Patient Type (Walk-in / Non walk-in)). **Walk-in** auto-books an appointment (doctor, appointment type OPD Consultation / Procedure / Telemedicine, room) → toast "Walk-in appointment booked".
- Row actions: View, Edit ("Edit Patient"), Archive (toast with undo → "Archive undone"), Link Portal ("Link Portal Access", email) / Unlink, WhatsApp (send appointment reminder → "Reminder sent"), Start Visit. Copy ID / patient code on click. "Export CSV".

## Known Inconsistencies & Duplicate Paths (worth stories)

1. **Dead legacy query params**: header notifications link to `/dashboard/inventory?tab=low-stock` and `?tab=expiry`; Pharmacy Desk "Inventory Control" and Counter link to `?tab=pharmacy-control(&section=shelf)`. InventoryWorkspace reads only `area`/`view`, so these land on **Today**. (Today's own queues use correct `area=stock&view=list&stock=LOW`.) PharmacyInventoryControl/ShelfIntelligence are orphaned.
2. **Invoice list reachable 3 ways**: `/dashboard/pharmacy/invoices`, Inventory → Sales → "Patient invoice history", and `/dashboard/billing` → Pharmacy Billing.
3. **Selling reachable 3 ways**: Pharmacy Billing (invoice builder), Pharmacy Counter "Walk-in bill"/"Start billing", Inventory → Sales → "Counter sales" (workflow COUNTER_SALE).
4. **Start a visit from ≥6 places**: appointment tile, Appointment Details dialog, Patients row, Patient detail, PatientProgressTracker, Visits "Start New Visit" (+ notification link `visits?appointmentId=`).
5. **Book an appointment 4 ways**: Calendar tab, Slots tab (two different schedulers), Walk-in patient creation, Patient detail/ProgressTracker "Book appointment".
6. **WhatsApp settings in two places** (header My Settings vs Users → WhatsApp Settings); **doctor availability in two places** (header vs Users → Working Hours).
7. **Role mismatches frontend vs backend**: NURSE sees Visits/Cancel Appointment but backend denies create/complete/delete; RECEPTION sees Pharmacy Desk/Billing but `/pharmacy/dashboard` and invoice create/checkout are ADMIN/PHARMACIST; MANAGER sees Users (read-only in practice) and Inventory (legacy endpoints 403); OWNER and DOCTOR have no Pharmacy sidebar links; ACCOUNTANT/LAB_TECH/PATIENT have nearly empty sidebars; "Therapist" mentioned in UI copy but not a real role.
8. **Orphaned components / unreachable APIs**: BillingManagement (clinic billing), StockPredictionDashboard, PharmacyDashboard, PharmacyPackageManager, PharmacyInvoiceBuilder (non-Fixed), PharmacyInventoryControl, ShelfIntelligence; audit-logs API, 1mg API, prescription refills, template version approval, appointment bulk-update.
9. `/test-transcribe` is a dev/diagnostic page in the production Admin nav and is not covered by middleware.
10. Procedures "Analytics" tab is a "coming soon" placeholder; Procedure History reads visits.
