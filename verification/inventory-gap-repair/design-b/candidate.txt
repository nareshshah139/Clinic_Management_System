Usage, written before the types
The operator opens an OCR draft and immediately sees invoice identity, stock status, the original, and an editable worksheet.
Every line shows product, batch, expiry, paid/free quantity, purchase rate, and tax. Errors appear beside the field.
Secondary commercial fields remain in a named row disclosure. A flagged secondary field opens that disclosure automatically.
An exceptions strip links to unresolved fields but does not make the operator acknowledge each field separately.
The bottom bar says “Confirm reviewed values & add stock”. Its help names the supplier, products, batches, expiry, quantities, and totals being confirmed.
The receipt variant says “Confirm & post bill” and “Stock received earlier. No stock is added again.”
The click is the explicit human confirmation of the current complete invoice. It saves that exact snapshot, reviews it, posts it, and reads back the authoritative status.
Save draft preserves unresolved flags and never posts. A successful local edit does not turn the whole invoice green.

Single-owner rules
All form mutations remain in PurchaseInvoiceEditor. Child controls receive values and commands, never their own copied draft.
Model the Domain changed the bulk design to a preview/applied union rather than independent preview, undo, and busy booleans.
Experience First changed the review design to field corrections plus one final intent, removing repeated field acknowledgements and the checkbox.
prepareReviewSnapshot computes a fresh immutable payload synchronously at the final click. It must not set React state and then call the old closure.
The snapshot contains actual printed totals. Never replace printed amounts with computed totals to silence reconciliation.
The same snapshot supplies flags, header, lines, checked dependencies, and saved payload. Apply its evidence to UI state only after accepting that intent.
Soft OCR uncertainty may be confirmed by this explicit whole-invoice action when its values are valid.
Missing/invalid values, upload-only issues, expired batches, real total mismatches, product ambiguity, missing catalogue metadata, historical holds, and stale/unknown state remain hard blockers.
Unknown flag categories require a visible manual issue, not silent blanket deletion. Reuse current cause-specific parsing and server validation.
The current catalogue proof must still match the current invoice generation and product identity. Confirmation itself must not invalidate it.
An edit clears final intent. A dependency edit invalidates prior evidence unless that complete dependent check is explicitly covered by the current input action.
Server-returned flags remain authoritative after saving; any new unresolved flag stops review/commit.

Bulk rules
Start with GST components and discount only. Exclude product identity, batch, expiry, quantities, prices, and printed totals.
Only explicitly selected row IDs are in scope. Preview includes names, old values, new values, and selected count.
GST changes use all three components explicitly so applying interstate IGST cannot accidentally retain CGST/SGST.
Validate the proposed full rows with existing numeric/discount/tax checks before enabling Apply.
Any invoice switch, row deletion, or intervening draft edit expires the preview. Selection never follows row indexes.
Apply is one local mutation and one generation invalidation. It does not call supplier, catalogue, draft-save, review, or stock APIs.
Undo restores the captured cells and associated review evidence only if they still equal the applied values and the same invoice is editable.
Unrelated later edits remain intact. If an affected cell changed again, explain that the batch undo has expired rather than overwriting newer work.
Unknown stock status, stale revision, posting in progress, or read-only permission disables Apply and Undo.

Tradeoffs accepted
We accept local additions to the mature editor in exchange for retaining one owner of invoice/revision/catalogue state and a short trace to posting.
We accept always showing the compact product/batch/expiry/quantity/rate fields in exchange for avoiding row-open clicks for ordinary OCR corrections.
We accept a limited set of shared terms in exchange for making bulk scope understandable and keeping identity/stock-affecting guesses out of it.

Alternatives considered
A separate review wizard hides form detail but adds navigation state and scatters correction, selection, and submission ownership across steps.
A generic spreadsheet engine offers broader reuse but exposes column adapters, validation metadata, and patch serialization to every caller for one editor.
An “accept all flags” button beside the existing checkbox adds an extra path and can discard hard failures. It does not remove the duplicated review model.
